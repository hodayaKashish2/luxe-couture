סטטוסים במערכת

סטטוסמשמעות
pending_owner_approvalממתין לאישור משכירה
pending_paymentהמשכירה אישרה — ממתין לתשלום
awaiting_admin_approvalדיווח תשלום — ממתין לאישור אדמין
confirmedהזמנה סופית ✅
cancelledבוטלה ❌
failedכשל תשלום (לא פעיל ב-UI)

1. תרשים ראשי — כל הזרימה

flowchart TD
    START([שוכרת בוחרת שמלה + תאריך + פרטים]) --> CHECK{תאריך תפוס?}
    CHECK -->|כן| ERR409[שגיאה: התאריך תפוס]
    CHECK -->|לא| SUBMIT[שליחת בקשת שריון]
    SUBMIT --> POA[pending_owner_approval]
    POA --> MAIL1[מייל למשכירה + שוכרת + אדמין]
    POA --> T24{עברו 24 שעות?}
    T24 -->|כן| REMIND[תזכורת למשכירה]
    T24 -->|לא| OWNER{החלטת משכירה}
    REMIND --> OWNER
    OWNER -->|מאשרת| PP[pending_payment]
    OWNER -->|דוחה| CANC1[cancelled]
    OWNER -->|48 שעות ללא מענה| CANC2[cancelled timeout]
    OWNER -->|שוכרת מבטלת| CANC3[cancelled]
    PP --> MAIL2[מייל: קישור לתשלום]
    PP --> PAY{שוכרת משלמת}
    PAY -->|ביט / העברה| AAA[awaiting_admin_approval]
    PAY -->|שוכרת מבטלת| CANC4[cancelled]
    AAA --> MAIL3[מייל לאדמין + שוכרת]
    AAA --> ADMIN{אדמין מאשר?}
    ADMIN -->|כן| CONF[confirmed]
    ADMIN -->|שוכרת מבטלת| CANC5[cancelled]
    CONF --> END([הזמנה סופית])
    CANC1 --> ENDC([בוטלה])
    CANC2 --> ENDC
    CANC3 --> ENDC
    CANC4 --> ENDC
    CANC5 --> ENDC

2. שוכרת עם חשבון vs בלי חשבון

flowchart LR
    subgraph WITH["שוכרת עם חשבון"]
        W1[פרטים מתמלאים אוטומטית] --> W2[site_user_id נשמר]
        W2 --> W3[מעקב בהזמנות שלי]
        W3 --> W4[יכולה לבטל]
        W4 --> W5[תשלום: אזור אישי או קישור]
    end
    subgraph WITHOUT["שוכרת בלי חשבון"]
        G1[ממלאה פרטים ידנית] --> G2[ללא site_user_id]
        G2 --> G3[מעקב במיילים בלבד]
        G3 --> G4[לא יכולה לבטל]
        G4 --> G5[תשלום: קישור מהמייל]
    end
    WITH --> SAME[אותה זרימת אישורים]
    WITHOUT --> SAME

3. שלב 1 — אישור משכירה (עד 48 שעות)

flowchart TD
    POA[בקשה חדשה pending_owner_approval] --> WAIT[ממתין להחלטת משכירה]
    WAIT --> DECIDE{משכירה בוחרת}
    DECIDE -->|אישור| APPROVE[pending_payment]
    APPROVE --> WIN[שוכרת שאושרה ממשיכה]
    APPROVE --> LOSE[בקשות אחרות לאותו תאריך → cancelled]
    DECIDE -->|דחייה + סיבה| REJECT[cancelled + מייל לשוכרת]
    DECIDE -->|48 שעות ללא מענה| TIMEOUT[cancelled + מייל timeout]
    POA --> REM24[אחרי 24 שעות]
    REM24 --> REMMAIL[תזכורת למשכירה]

4. שלב 2 — תשלום (ביט / העברה בנקאית)

flowchart TD
    PP[pending_payment] --> CHOOSE{בחירת אמצעי}
    CHOOSE -->|ביט| BIT[אפליקציית Bit]
    CHOOSE -->|העברה| BANK[העברה בנקאית]
    BIT --> REPORT[אישור תשלום]
    BANK --> REPORT
    REPORT --> AAA[awaiting_admin_approval]
    AAA --> MAILS[מייל לאדמין + שוכרת]
    PP --> BLOCK{תשלום לפני אישור משכירה?}
    BLOCK -->|כן| ERR400[שגיאה 400]

5. שלב 3 — אישור אדמין

flowchart TD
    AAA[awaiting_admin_approval] --> ADMIN{אדמין}
    ADMIN -->|מאשר תשלום| CHECK{תאריך פנוי?}
    CHECK -->|כן| CONF[confirmed]
    CHECK -->|לא| ERR409[שגיאה 409]
    CONF --> ACTIONS[rental_count+1, מייל אישור]
    ADMIN -->|דחיית תשלום| NOREJECT[אין בקוד — רק אישור]

9. Sequence — לפי שחקן

sequenceDiagram
    participant R as שוכרת
    participant SYS as מערכת
    participant O as משכירה
    participant A as אדמין
    R->>SYS: בקשת שריון
    SYS->>O: מייל בקשה
    SYS->>R: מייל אישור קבלה
    SYS->>A: מייל הודעה
    Note over O: עד 48 שעות
    SYS->>O: תזכורת 24ש
    alt משכירה מאשרת
        O->>SYS: אישור
        SYS->>R: קישור תשלום
        R->>SYS: דיווח ביט/העברה
        SYS->>A: לאישור
        A->>SYS: אישור תשלום
        SYS->>R: הזמנה מאושרת
    else משכירה דוחה
        O->>SYS: דחייה
        SYS->>R: נדחית
    else 48 שעות ללא מענה
        SYS->>R: בוטלה אוטומטית
    end
